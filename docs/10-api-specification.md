# 10 — API Specification

## Overview

DataSage exposes a RESTful JSON API under `/api/v1/`. This document catalogs all endpoints, request/response schemas, pagination, filtering, error format, and versioning strategy.

The live API documentation is auto-generated by FastAPI at `/docs` (Swagger UI) and `/redoc` (ReDoc) in development mode.

---

## Conventions

| Aspect | Convention |
|--------|-----------|
| Base URL | `/api/v1` |
| Content type | `application/json` |
| Authentication | `Authorization: Bearer <access_token>` |
| Pagination | Cursor-based: `?cursor=<opaque>&limit=20` |
| Sorting | `?sort=field&order=asc|desc` |
| Filtering | Query parameters per field: `?bhk=3&min_price=5000000` |
| Error format | `{"error": {"code": "...", "message": "...", "request_id": "..."}}` |
| IDs | UUIDs |
| Timestamps | ISO 8601 with timezone: `2026-09-21T15:30:00+05:30` |
| Currency | Integer INR (whole rupees) |

|--------|------|------|-------------|

## Pagination

### Cursor-Based Pagination

Used for all list endpoints. Avoids offset-based pagination issues (inconsistent results on data changes).

```json
// Response format
{
  "data": [...],
  "pagination": {
    "next_cursor": "eyJpZCI6IjEyMyIsImNyZWF0ZWRfYXQiOiIyMDI2LTA5LTIxIn0=",
    "has_more": true,
    "total_count": 150
  }
}
```

**Cursor** is a base64-encoded JSON object containing the sort field value and ID of the last item. This allows keyset pagination:

```sql
WHERE (created_at, id) < (:cursor_created_at, :cursor_id)
ORDER BY created_at DESC, id DESC
LIMIT 21  -- Fetch limit+1 to check has_more
```

## Rate Limiting

| Endpoint Group | Limit | Window |
|---------------|-------|--------|
| Auth (login, register) | 10 requests | 1 minute |
| Search / list | 100 requests | 1 minute |
| ML predictions | 20 requests | 1 minute |
| Admin | 200 requests | 1 minute |
| Default | 100 requests | 1 minute |

Rate limit headers:
```
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 95
X-RateLimit-Reset: 1695300000
```

When exceeded:
```json
// 429 Too Many Requests
{
  "error": {
    "code": "RATE_LIMIT_EXCEEDED",
    "message": "Too many requests. Please try again in 45 seconds.",
    "retry_after": 45
  }
}
```

## Standard Error Response

All errors follow this format:

```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Human-readable message",
    "request_id": "req_abc123def456",
    "details": {}  // Optional: validation errors, missing fields, etc.
  }
}
```

| HTTP Status | Error Code | When |
|-------------|-----------|------|
| 400 | BAD_REQUEST | Malformed request body |
| 401 | UNAUTHORIZED / INVALID_CREDENTIALS | Missing/invalid/expired token |
| 403 | FORBIDDEN | Insufficient role/permissions |
| 404 | NOT_FOUND | Resource doesn't exist |
| 409 | CONFLICT | Duplicate resource (e.g., email already registered) |
| 422 | VALIDATION_ERROR / INSUFFICIENT_DATA | Invalid input / missing ML features |
| 429 | RATE_LIMIT_EXCEEDED | Too many requests |
| 500 | INTERNAL_ERROR | Unexpected server error |
| 503 | SERVICE_UNAVAILABLE / MODEL_NOT_LOADED | ML model or dependency unavailable |
